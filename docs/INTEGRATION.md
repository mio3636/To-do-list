# 最终整合说明

## 三份提交如何进入项目

| 输入文档 | 原始内容 | 最终位置 |
| --- | --- | --- |
| 新建 文本文档.txt | load_tasks/save_tasks、任务新增/展示/状态/删除/筛选、菜单 | console.py 保留函数名称与功能，统一调用 TaskService；迁移和字段归一化在 migration.py |
| 新建 文本文档 (2).txt | TaskRepository、JsonTaskRepository、兼容函数、存储测试 | storage.py 保留统一接口及原子替换；test_storage.py 整合三项原始测试并补齐迁移与失败保护 |
| 新建 文本文档 (3).txt | 六项命令行 main 菜单 | console.run_menu()，由 main.py 的 --cli 分支装配；与桌面入口共存 |

原始文档分别保存在 contributions/member1_original.txt、member2_original.txt、member3_original.txt，内容不变，仅供贡献追溯。文档中的中文说明、重复 main() 以及其他嵌入文字不作为可执行 Python 代码导入。

本次不是把三个独立程序串联运行，而是合并它们的任务功能和菜单，统一使用既有 Task 模型、TaskService 和 JSON 仓储。避免三套重复函数互相覆盖。

## 兼容与修正

- `description` 对应 `title`；`completed/in progress` 对应布尔 `completed`。
- 优先级 1/2/3 对应高/中/低；Study/Work/Leisure 对应学习/工作/生活。
- 旧列表 JSON 可读取，首次保存前留原始备份，再转换为 version=1。
- CLI 函数参数从可变字典列表调整为 TaskService，防止绕开校验和保存。函数名保持可追溯，调用方式以 console.py 为准。
- 菜单提示从原先的 1-7 修正为实际存在的 1-6。
- 非数字序号、越界序号、非法状态和日期都给出提示，不导致菜单异常退出。
- 筛选展示保留原始任务序号，避免对已完成列表中的任务误操作。
- 每次修改立即持久化；保存失败时不更新业务层内存；删除须确认。
- 存储模块中重复的业务函数移到 console/services，不再混合职责。
- 原提交遇到损坏 JSON 返回空列表，容易在退出时覆盖原数据。最终实现改为 StorageError，保留文件并提示。相应测试明确验证异常和原文保留。
- 原存储测试使用固定 test_tasks.json，现改为临时目录，避免测试覆盖真实文件。
- CLI 与帮助信息不依赖 Tkinter；无图形桌面的环境也可使用 --cli。

## 实际验收

1. 26 项单元及集成测试：核心任务、六项菜单、日期边界、无效输入、数据互通、旧格式迁移、BOM 文件、备份冲突、写入失败保护。
2. Tkinter 集成脚本：启动窗口、添加、详情保存、完成、切换视图、搜索、分类、删除与撤销、CLI 写入后由桌面服务读取。
3. 两种入口帮助与命令行端到端执行，重启后数据保留。

上述测试使用临时数据，不触碰用户的真实任务。完整运行指令见根目录 README。

## 交付边界

项目为单用户本地应用，桌面版支持详情编辑，CLI 保留三份提交中的六项菜单。两种模式切换使用；同一文件不支持多实例并发写入。桌面详情为手动保存，切换任务或筛选前应先保存。子任务、重复任务、提醒、登录和云同步不在本次整合范围内。
